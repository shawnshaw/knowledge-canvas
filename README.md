# Knowledge Canvas

把真实 Markdown 文件作为卡片放到自由画板中，并在画板内预览、编辑、编组和建立关系。正文始终保存在原 Markdown；`.canvas` 文件只保存文件引用、布局、关系、分组、折叠状态、卡片颜色和连线形态。还可以从原文里剪下一段做成「摘录贴纸」——它不新建文件、不复制知识库、不改原文，只保留一条回到原文的引用。

## 使用

1. 启用插件后，执行命令 `Knowledge Canvas: Open board`，或点击左侧画板图标。
2. 用顶栏的「画布」选择器切换工作区，点旁边的「＋」新建画布。
3. 双击画板空白处或点击“便利贴”，创建 Markdown 笔记（默认落在 `Inbox/Canvas`，可在设置里改）。
4. 在文件菜单选择“加入知识画板”，把已有 `.md` 文件加入画板。
5. 单击选择卡片；再次单击或按 `Enter` 打开浮动预览；按 `Cmd/Ctrl+E` 编辑。
6. 从卡片右侧锚点拖到另一张卡片建立关系。双击关系线可输入任意标签。
7. 右键关系线可改单向／双向／无方向、**路线（曲线／直线／折线）**、虚实、颜色，或同步为 Markdown 双链；菜单末尾可以「**删除关系**」。
8. 卡片标题行的三角按钮可折叠／展开；折叠只收起正文，不影响 Markdown、搜索和关系。
9. 左上角的圆形「＋」是画板工具入口，**默认折叠**。点开后展开成胶囊，显示「＋便利贴／导入文件／导入文件夹／布局」以及当前选中对应的编组操作；再次点击、按 `Escape` 或点击工具栏外部都会收起。
10. 在浮动编辑器的编辑模式里右键：有选区时菜单包含「生成摘录贴纸」、格式项和「添加时间戳」；**没有选区时也可以对光标所在段落「添加时间戳」**。
11. 点击摘录贴纸即可回到原文并选中被摘的那段话。
12. 选中至少两张未分组卡片后可「编组」；选中一个分组框后可「解除分组」或「删除分组框」。摘录贴纸和文件卡一样可以编组。
13. 顶栏「画布」选择器 →「＋」新建画布 → 右侧紧邻的「**导入 ReadFlow**」把微信读书摘录批量加入**当前画布**；空画布也保留同一个入口。
14. 顶栏右上角的「重载」按钮，点开有两个选项：「重载画板数据」重新从磁盘读取当前画布；「重载插件代码」关闭并重新启用插件，刚替换的 `main.js` 立即生效（不用重启 Obsidian）。浮动编辑器有未保存内容时，插件重载会被拦下并提示先保存。
15. 右键卡片：第一项是「**颜色**」（六色 palette popover）；文件卡另有「预览／编辑／折叠／从画布移除」，摘录贴纸有「回到原文／折叠／从画布移除」。

## 多画布

- 每张画布是一个独立的 `.canvas` 文件，节点、关系、分组和折叠状态互不影响。
- 旧画布 `Canvas/知识画板.canvas` 保持原样，作为默认项，不迁移、不重写。
- 新建画布写入 `Canvas/Knowledge Canvas/<名称>.canvas`；同名文件存在时阻止创建，不覆盖也不追加随机后缀。
- 画布清单直接来自文件系统（默认画布 + 专用目录内的 `.canvas`），`data.json` 里的 `lastBoardPath` 只用来记住上次打开项，不存第二份注册表。记住的画布被移走时会安全回退到默认画布。
- 切换画布会先关闭浮动编辑器并等待画板写入落盘；任一步失败都会保留原来的画布、选择和未保存正文。
- 本阶段不提供嵌套画布、跨画布拖拽或批量画布管理。
- 重命名 Markdown 文件会更新**所有**受管画布的引用；某张画布损坏时只报告该画布，不会中断其他画布，也不会覆盖它。

## 画布重命名与删除

- 顶栏最右侧的「···」是画布管理菜单，只有 `Canvas/Knowledge Canvas/` 下的普通画布可用；默认画布 `Canvas/知识画板.canvas` 与 ReadFlow 书板在此禁用并说明原因。
- **重命名**：只改画布本身；若该画布有专属笔记文件夹，可勾选「同时重命名专属笔记文件夹」（默认不勾选）。勾选时新文件夹名跟随新画布名，父目录不变，并同步更新 `kcMeta.noteFolder` 以及当前画布与其他画布中指向旧目录的 Markdown 引用。
- **删除**：画布文件进入 Obsidian 废纸篓；「同时删除专属笔记文件夹」默认不勾选，且仅当该文件夹为空、或其中 Markdown 全部被当前画布引用时才可勾选。确认后会重新扫描一次，内容有变化就取消整个删除。
- 两种情况都不会移动或删除 Markdown 以外的文件；删除完成后切回默认画布，ReadFlow 中指向该画布的绑定会被同步更新或清除。
- 顺序与回滚：先关编辑器、再 drain 写队列，最后才动文件。文件夹已重命名而后续步骤失败时，会尝试恢复旧路径；恢复失败时同时报告两个路径，不会假装成功。

## 批量整理、吸附与定位

- **框选**：在画板空白处按住左键拖拽即出现选择框，命中按世界坐标计算，20%／100%／300% 缩放下一致；按住 `Cmd/Ctrl/Shift` 拖拽是增量选择。
- **点选**：单击选中一张；`Cmd/Ctrl/Shift + 单击`切换单张；`Cmd/Ctrl+A` 在画板聚焦且不在输入框／编辑器内时选择全部卡片与分组框；`Escape` 清空选择。
- **批量拖动**：拖动任意已选卡片时全部已选对象保持相对距离移动；选中分组时分组框和成员作为同一个移动单位，同一张卡片不会被位移两次。拖动过程中只更新内存和 DOM，松手才保存一次。
- **布局**（画布右键、多选右键或工具入口的「布局」）：Grid 网格、水平排列、垂直排列、左／水平居中／右对齐、顶部／垂直居中／底部对齐、水平／垂直等距分布。没有选择时命令禁用，不会静默整理整张画布。
- **吸附**：拖动时对其它卡片的左右边缘、水平中心、上下边缘、垂直中心吸附，阈值约 8 屏幕像素并按当前缩放换算；同一方向只取最近且稳定的候选，并显示细参考线，拖动结束立即移除。画布右键的「吸附对齐」是本次 View 会期内的开关（`aria-pressed`），按住 `Option/Alt` 可临时关闭。
- **定位内容**：右下角缩放控件左侧的定位按钮把全部卡片纳入视野并保留约 64px 边距，缩放始终限制在 0.2–3；空画布只提示「画布暂无内容」，不移动视口。
- 布局、编组、拖动都走「克隆 → 保存 → 安装」；保存失败会恢复拖动前的几何与选择，并提示画板未改动。

## 导入文件与文件夹

- 「导入文件」从库中选择单个 Markdown；「导入文件夹」递归导入文件夹下所有 `.md`，只新增卡片，不复制、不移动、不改写源文件。
- 已在当前画板的文件、同一批里重复的路径和非 Markdown 文件都会被跳过；整批只保存一次、渲染一次。
- 新卡片按确定性的 Grid 排在现有内容右侧，不覆盖已有卡片；完成后提示新增／跳过／失败数量。取消选择或扫描失败时画布不变；扫描超过 300ms 会显示进行中状态并禁用重复提交。

## 画布专属笔记目录

- 新建画布时可勾选「同时创建此画布的专属笔记文件夹」，默认不勾选。勾选后目录为 `<全局默认便利贴目录>/<规范化画布名称>/`，并写入 `.canvas` 顶层的可选扩展字段 `kcMeta`：

```json
{ "kcMeta": { "version": 1, "noteFolder": "Inbox/Canvas/画布名称" } }
```

- `kcMeta.noteFolder` 优先于插件设置里的全局目录，**只影响之后新建的便利贴**；导入已有文件仍只引用原路径，不会移动。旧画布没有该字段时继续正常打开。目录创建失败时不会留下半有效画布。

## 段落与摘录时间

- 编辑器右键「添加时间戳」会在段落后面写入一条不影响渲染的 HTML 注释：

```markdown
某一段正文。

<!-- kc-time: {"createdAt":"2026-10-17T14:30:00.000Z"} -->
```

- 段落文字真正改变并保存成功后才会追加 `updatedAt`，`createdAt` 始终保留；只移动光标、只预览或不改内容保存都不会更新时间。frontmatter、空行、fenced code block 和 marker 本身都不会被当作段落，已有 marker 不会重复插入。
- 新摘录会记录 `createdAt`；源文保存成功后，若原 quote 仍能定位则不动时间，无法定位时给该摘录写入同一保存时刻的 `updatedAt`，摘录卡片底部显示「创建于 …」和（如有）「源文更新于 …」。
- 正文已保存但画板写入失败时，只提示「正文已保存，但摘录更新时间未写入」，不回滚 Markdown，画板仍可重试。

## 移除便利贴与源文件

`Delete`、`Backspace`、「从画板移除」和缺失卡片的清理都会打开同一个确认弹窗，不会再静默移除。

- 默认只移除当前画布中的所选卡片和它们的连线，**Markdown 源文件保留**。
- 「同时将 Markdown 源文件移入废纸篓」默认**不勾选**，必须手动勾选才会删除源文件。
- 删除只走 Obsidian Trash（`app.fileManager.trashFile`），**从不永久删除**。
- 勾选后会先只读扫描库里**所有** `.canvas`：任一枚举文件仍被其他卡片或其他画布引用，或任一画布无法读取／解析，都会停用该复选框并说明原因，只保留「仅从画板移除」。
- 已经缺失的源文件只移除卡片，不会执行 Trash。
- 顺序是先克隆画板 → 校验并保存成功 → 再逐个把源文件移入废纸篓。画板保存失败时原画板与选择完全不变。
- Trash 部分失败不会回滚已完成的移除，失败文件会逐个列出且仍留在库中。
- 删除分组框只删除分组节点，不会删除组内卡片、连线或 Markdown。
- 删除摘录贴纸只移除该节点与关联连线，不产生任何源文件删除目标。
- 选中一条关系线后按 `Delete`／`Backspace` 只删除这条关系：关系不承载任何 Markdown 源文件，所以不弹确认框，也不会出现「移入废纸篓」选项。

## 折叠与分组

- 折叠会把卡片收成紧凑的标题行；文件里的原始高度不变，展开即恢复原尺寸。关系端点按当前渲染高度计算。
- 折叠卡片仍可选择、拖动、建立关系和按 `Enter` 预览，只是不再加载正文摘要。
- **折叠不是权限控制，也不是加密**：Markdown、搜索和源文件始终可访问。
- 分组使用标准 JSON Canvas `group` 节点加扩展字段 `members`，分组框排在成员卡片之前，因此在原生 Canvas 和插件内都呈现为背景框。
- 一张卡片最多属于一个分组；分组不能嵌套分组，也不能连接关系线；至少两张未分组卡片才能编组。文件卡和摘录贴纸都算卡片。
- 拖动分组框会整体移动分组框与成员——文件卡、摘录贴纸、原生文本卡都会跟着走；单独拖动、缩放或折叠成员时分组框会自动重新包围。
- 折叠对文件卡、摘录贴纸和原生文本卡一致可用；分组框本身不可折叠。
- 「解除分组」只删除分组框，卡片、关系和 Markdown 全部保留。
- 分组框可以键盘操作：`Tab` 聚焦后 `Enter` 或空格即选中该分组，展开的工具入口随即露出「解除分组／删除分组框」；`Escape` 清空选择。选区高亮与 `:focus-visible` 焦点环对卡片和分组框一致。
- 本阶段不支持组嵌套、组折叠、组间连线、手动调整组框大小或跨画布移动。

## 卡片颜色与视觉角色

颜色保存在 JSON Canvas 标准 `node.color` 里，neutral **不写这个字段**。

| 卡片 | 默认外观 | 颜色行为 |
|---|---|---|
| 普通 Markdown 文件 | 中性 surface、1px 边框、8px 圆角、克制阴影 | 默认 neutral，可手动改色 |
| 手工便利贴 | 整块柔和纸色 | 创建时从五个非 neutral 预设随机取色，可改 |
| ReadFlow | 中性 surface + 4px 左侧来源色线 + `READFLOW · 原文摘录` | 默认 blue，只影响那条色线 |
| 摘录贴纸 | 中性 surface + 4px 左侧来源色线 | 默认 neutral，可改 |
| 缺失文件 | 中性 surface + dashed 边框 | 不用颜色掩盖错误状态 |

- 预设与取值：coral `"1"`、yellow `"3"`、green `"4"`、blue `"5"`、purple `"6"`；neutral 不写字段。
- 新便利贴的随机色**立即写进画布**，重新打开、插件 reload、Obsidian 重启后都不会变。
- 右键卡片第一项是「颜色」，打开锚定卡片的小型 popover：六个色块、当前色带 checkmark，支持 `Tab`／方向键循环、`Enter`／空格确认、`Escape` 取消、点击外部关闭，关闭后焦点回到卡片。
- 选择后**先保存再更新画布**；保存失败会恢复旧颜色并给出提示。
- ReadFlow 的默认 blue **只在渲染时生效**，不会每次渲染改写画布。
- V1 只提供这六个预设，不做任意 RGB／Hex、渐变或纹理。颜色不是唯一区分手段：类型标识、`READFLOW · 原文摘录` 文案与 dashed 边框都独立可辨。

## 连线

- 路线保存在扩展字段 `edge.kcRoute`，取值 `curve | straight | elbow`；缺字段的旧关系按 `curve` 渲染，**不需要迁移文件**。
- `curve` 是轻量三次贝塞尔；`straight` 是直线；`elbow` 是正交折线，拐点带轻微圆角。
- 起点与终点落在**卡片边界**，不再从卡片中心穿出；标签取实际路径的视觉中点，仍可双击编辑。
- 默认线宽 1.5px、选中 2.5px，箭头收小；透明命中路径 14px，容易点中。
- 右键关系线的菜单顺序：名称 → 方向 → 路线 → 线型 → 颜色 →（两端都是文件卡时）Markdown 双链 → 删除关系。
- 「删除关系」走与 `Delete`／`Backspace` 相同的 relation-only 链路：只删除这条关系，不动两端卡片与源文件，也不会出现「删除源文件」选项。

## ReadFlow 批量导入

- 只识别 Metadata Cache 中 `frontmatter.type === "highlight"` 的 Atomic Markdown；未发现时提示先在 ReadFlow 设置中启用独立摘录文件并重新同步。
- 选择器支持按书籍／章节／状态筛选、按摘录正文或想法搜索、多选与“全选当前结果”。
- 已在当前画布的摘录显示「已添加」并禁选；出现在其他画布不影响导入。
- 新卡片按书籍分区块、按章节分列，先按 `created` 再按文件名稳定排序，统一放在既有内容**右侧** 96px 处；既有卡片和分组不会被移动。
- 写入前会再次按文件路径去重并复查文件是否仍在库中；画板保存失败时本批新增全部回滚。
- **只读边界**：只读取 Atomic Markdown 与 Metadata Cache。不读取或修改 ReadFlow 的 `data.json`、Cookie、同步状态，也不触碰 `.obsidian/plugins/readflow/**`，不触发同步，不写回微信读书。

## 摘录贴纸

从原文剪一段，做成可移动、可连接、可编组、可回到原文的「阅读切片」。源文件始终是唯一事实来源。

- 在浮动编辑器进入编辑模式，选中一段**非空**文本后右键 →「生成摘录贴纸」。没有选中内容或只选中空白时不会出现这个动作，也不会出现格式菜单。
- 创建前会先把编辑器里尚未保存的修改写回源文件。**保存失败或出现外部修改冲突时不会创建贴纸**，画布也不写，未保存的文本与恢复条照旧留在编辑器里。
- 贴纸落在源文件卡**右侧**；连续创建会自动错位，不会完全重叠。
- 贴纸显示三样东西：原文摘录、源文件名称、「摘录」类型标识。
- **不新建 Markdown、不复制知识库文件、不修改原文。** 贴纸是 JSON Canvas 标准 `text` node，引用关系放在 `kcExcerpt` 扩展字段里，因此 Obsidian 原生 Canvas 也能把它当作普通文本卡显示。
- 点击贴纸回到原文，定位顺序为：① 保存的 `start/end` 仍与 `quote` 一致 → 直接用原偏移；② 否则全文查找 `quote`，唯一命中就用它；③ 多处命中时结合保存的 `prefix/suffix` 选最可信的一处；④ 都定位不到就展示保存的摘录并提示「原文已变化，无法自动定位」，**不改源文件**。多处命中且上下文**全部失效**时会直接判为无法定位，不会凭旧偏移猜一个位置把你带到错误段落。
- 贴纸可以移动、缩放、折叠、建立关系、加入分组，也能被搜索——搜索范围包含摘录正文与源文件路径。
- 切到「结构大纲」时只列出文件卡以及文件卡之间的关系；摘录贴纸和原生文本卡仍留在自由画板上，不会让该模式报错。
- 关系线两端都是文件卡时才有「同步为 Markdown 双链」；与摘录贴纸相连的关系仍可改名称、方向、线型和颜色，只是没有可写入的 Markdown 目标。
- 删除贴纸只移除画布节点与关联连线，**永远不提供「同时删除 Markdown 源文件」**。
- 反过来：只要当前或其他画布还有摘录指向某个 Markdown，删除该文件卡时就**禁止**勾选把源文件移入废纸篓。
- 重命名 Markdown 时，所有受管画布里的 `kcExcerpt.sourceFile` 会同步更新。

## 编辑器格式菜单（第一期）

只在编辑模式且存在有效选择时提供。所有格式变化都通过现有的编辑器会话执行，因此自动保存、外部修改冲突检测和失败恢复都不变。

- 生成摘录贴纸
- 加粗 `**text**`、斜体 `*text*`、高亮 `==text==`、行内代码 `` `text` ``
- 引用：选中行加 `> `；无序列表：选中行加 `- `。逐行独立 toggle，所以半引用的一段不会叠成 `> > `
- 标题：正文、H1、H2、H3，只操作完整行

已带对应标记时执行最小 toggle，格式化后保持合理的选区／光标。明确不做：任意字体／字号／文字颜色、WYSIWYG、HTML `<span style>`，也不引入 CodeMirror / TipTap / ProseMirror 之类依赖。

## 设置

设置 → 第三方插件 → Knowledge Canvas → 选项：

- **便利贴存放文件夹**：新建便利贴的 Markdown 文件放在这里。留空回退到默认目录 `Inbox/Canvas`。目录不存在时会在首次新建便利贴时自动逐级创建；改完立即生效，不需要重启 Obsidian。输入框下方实时提示规范化结果与「已存在 / 将自动创建」状态，右侧按钮可恢复默认值。

## 数据格式

- 默认画布：`Canvas/知识画板.canvas`
- 新建画布目录：`Canvas/Knowledge Canvas/`
- 默认便利贴目录：`Inbox/Canvas`（可在设置中修改）
- 卡片节点使用 JSON Canvas `type: file` 与 `file` 引用，可选 `collapsed: true`。
- 卡片可选 `color`，取 JSON Canvas 预设 `"1"`／`"3"`／`"4"`／`"5"`／`"6"`（coral／yellow／green／blue／purple）。**neutral 不写该字段**；非法值会被拒绝并报明确加载错误，手写的 `null` 按 neutral 读取。
- 关系可选 `kcRoute`，取 `curve`／`straight`／`elbow`。缺省即 `curve`，所以写入默认值时不会留下这个字段；非法值会被拒绝。
- 摘录贴纸使用 JSON Canvas 标准 `type: text` node，`text` 存 `> 摘录内容` 供原生 Canvas 降级展示；扩展字段 `kcExcerpt`（`version` / `sourceFile` / `quote` / `start` / `end` / `prefix` / `suffix`）保存引用关系。**不保存源文件副本**。
- `kcExcerpt.sourceFile` 必须是 Markdown 路径。**校验与删除引用扫描共用同一条规则**（去掉首尾空白后必须以 `.md` 结尾），所以不会出现「解析通过、扫描却忽略」的中间状态。
- 同一个节点上的 `file` 与 `kcExcerpt.sourceFile` 若都是有效 Markdown 引用，**两条都会被纳入删除保护**——不允许用其中一个盖住另一个。
- 没有 `kcExcerpt` 的纯 `text` node 也照常打开，按只读文本卡渲染（Obsidian 原生 Canvas 保存时可能丢未知字段，拒绝它会锁死画布）。`kcExcerpt` 存在但字段非法时会报明确加载错误并保持只读保护。
- 分组节点使用 JSON Canvas `type: group`，基础字段符合 JSON Canvas 1.0，第三方工具可正常显示分组框；`members` 是可忽略的扩展字段，可以引用文件卡或摘录贴纸。
- 节点必须有有限且为正的 `x`／`y`／`width`／`height`。
- 边使用 JSON Canvas 的 `fromNode`、`toNode`、`fromEnd`、`toEnd`，并可带自由文本 `label`；边只能连接卡片。
- 旧画布不需要迁移即可读取。
